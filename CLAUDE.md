# School Dashboard for Canvas: project context

A local Next.js (App Router, plain JavaScript, Tailwind v4) dashboard that pulls a student's Canvas data into one screen. It runs on the user's own Windows PC, never deployed publicly. Owner: Jojo (GitHub: GunzRuls), a Florida Poly student. The repo is public so classmates can use it.

## How it runs

- Classmates install with `School-Dashboard-Setup.exe` from GitHub Releases. `.github/workflows/release.yml` (on release published, or manual dispatch → artifact) runs `npm ci`, `BUILD_STANDALONE=1 npm run build` (standalone output only in that mode, see `next.config.mjs`), fails if `.env*`/`dashboard-*.json`/logs are in `.next/standalone`, downloads the matching `node.exe` and checks its SHA256, then compiles `installer/setup.iss` (Inno Setup) and attaches the .exe. Installed layout under `%LOCALAPPDATA%\Programs\School Dashboard`: `node\node.exe`, `app\` (standalone + `.next\static`), `launcher\` (start/stop scripts, icon), `unins000.exe`. Per-user install, no admin. Never change the `AppId` GUID in setup.iss (Windows uses it to match updates).
- Installed mode: `start-dashboard.ps1` detects `node\node.exe` + `app\server.js` and runs node with the full server.js path (so `stop-dashboard.ps1` can match it), with `HOSTNAME=127.0.0.1`, `PORT=3000`, `DASHBOARD_AUTO_STOP=1`, `DASHBOARD_DATA_DIR=%APPDATA%\School Dashboard` (personal files + `server.log`), `DASHBOARD_INSTALL_DIR`. `lib/dataDir.js` resolves personal file paths (falls back to the project folder); its `/*turbopackIgnore: true*/` comment prevents whole-project tracing, and `outputFileTracingExcludes` is a second guard. Don't use a bare `"**"` key there: it dropped Next's own route runtime from the trace. In Settings, installed mode shows "Get the latest version" (releases link) instead of Reinstall, and Uninstall runs `unins000.exe`, which asks whether to delete the AppData folder.
- Updates (`lib/updates.js`, `app/api/update`, `app/components/UpdateNotice.jsx` in the top bar): only when installed (`DASHBOARD_INSTALL_DIR`) and `DASHBOARD_VERSION` is set. The workflow sets it from the tag (`v1.2.0` → `1.2.0`; manual runs `0.0.0-dev`), and `next.config.mjs` inlines it at build time. GET checks `api.github.com/repos/GunzRuls/canvas-dashboard/releases/latest` (cached 12 h). POST (same-origin) downloads `School-Dashboard-Setup.exe` only from this repo's release download URL, verifies GitHub's `sha256` asset digest, saves it to %TEMP%, and runs it with `/SILENT`; the `[Run]` entry intentionally lacks `skipifsilent` so the dashboard reopens after. Releases must use increasing numeric tags.
- Running from source: double-click `Install.cmd` (checks Node, stops a running server via `launcher/stop-dashboard.ps1`, deletes `.next`, `npm ci`, runs `launcher/create-shortcut.ps1` for the desktop icon, then launches). Rerunning it is the clean reinstall; settings files are kept. A prebuilt .lnk can't be shipped because shortcuts hold absolute paths.
- `Uninstall.cmd` → `launcher/uninstall.ps1`: stops the server, removes the desktop shortcut only if it points at this folder, then either deletes the whole folder (a hidden PowerShell waits for the uninstall window's process to exit first) or removes `node_modules`/`.next`/log and optionally the personal files. `stop-dashboard.ps1` only kills node.exe processes whose command line contains this folder's path.
- Settings has Reinstall / Uninstall buttons: `POST /api/maintenance` (same-origin only, `lib/sameOrigin.js`) runs `start "" Install.cmd|Uninstall.cmd` detached so the script outlives the server it stops.
- The app icon (`app/favicon.ico`, `app/icon.png`) is the same art as `launcher/dashboard.ico`; Chrome/Edge `--app` windows use it for the taskbar button.
- `.gitattributes` forces CRLF for `*.cmd`/`*.ps1` so GitHub ZIP downloads run correctly.
- Normal use is production mode through the desktop launcher (`launcher/start-dashboard.ps1`): it checks port 3000, rebuilds only if `app/`, `lib/`, `instrumentation.js` or `package.json` are newer than `.next/BUILD_ID`, then runs `npm run build && npm run start` in a hidden cmd (output to `launcher/server.log`, gitignored) with `DASHBOARD_AUTO_STOP=1`, shows a small WinForms "Starting..." box meanwhile, and opens Chrome or Edge with `--app=http://localhost:3000`.
- Auto-stop: `instrumentation.js` starts `lib/autoStop.js` only when `DASHBOARD_AUTO_STOP=1`. Every page (via `app/components/KeepAlive.jsx` in the layout) POSTs `/api/alive` every 20 s and sends `?closing=1` on pagehide. The server exits 45 s after a close with no further check-in, or after 10 min of silence (minimized windows can be throttled). A long gap between ticks (PC asleep) resets the clock. Plain `npm run start`/`npm run dev` never auto-stop.
- The server binds to 127.0.0.1 only (`-H 127.0.0.1` in both scripts) so nobody on the same Wi-Fi can reach it. Keep it that way; `/api/config` can change where the token is sent.
- `proxy.js` (Next 16's renamed middleware) guards every request against websites in the user's own browser: the Host must be localhost/127.0.0.1/[::1] (blocks DNS rebinding), and any non-GET/HEAD/OPTIONS request needs an Origin whose host equals the Host (blocks CSRF), except `/api/alive` (harmless; beacons may lack Origin). Routes that change things keep their own `fromThisApp` check as a second layer. `next.config.mjs` adds X-Frame-Options DENY + CSP frame-ancestors 'none' (no clickjacking), CORP same-origin, nosniff, and Referrer-Policy no-referrer. Any new API route is covered automatically; don't add exceptions without a reason. Scripts calling the API (the email task) must send an Origin header.
- Secrets at rest (`lib/secrets.js`): `SECRET_FIELDS` are stored as `dpapi:<base64>` using Windows DPAPI, CurrentUser scope, via one PowerShell call per batch with values on stdin (never argv). `lib/config.js` caches the decrypted settings keyed by the file's mtime+size, migrates plain-text secrets on first read, and a value that can't be decrypted (copied from another PC/account) reads as empty so the app asks again. `.env.local` fallbacks are not encrypted (the user's own file).
- Port: the launcher scans 3000–3010. It reuses a port where `/api/health` reports this copy (`root` = install dir or project folder), otherwise takes the first free port, sets `$env:PORT`, and explains the switch once per blocking program (MessageBox; remembered in `port-warning.txt`, gitignored; the email task logs it instead). Nothing else hard-codes 3000.
- For development use `npm run dev` (stop the launcher's server first).
- PowerShell on this machine needed `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` for npm/npx.

## Configuration (setup screen, never commit)

On first launch `app/page.js` redirects to `/setup` until a Canvas address and token exist. `/setup` doubles as the Settings screen (Settings button in the top bar). Saving in Settings stays on the page: it empties the secret boxes, shows "✓ Saved", and calls `router.refresh()` (no full reload) so the token ending, email status and calendar list update; the user asked for this. Canvas is required; Google Calendar and Resend are optional. `lib/config.js` is the only place settings are read: `getConfig()` reads `dashboard-config.json` (gitignored) fresh on each call, falling back per key to `.env.local` (`CANVAS_BASE_URL`, `CANVAS_TOKEN`, `GOOGLE_CALENDAR_ICS_URL`, `DIGEST_PROVIDER`, `GMAIL_ADDRESS`, `GMAIL_APP_PASSWORD`, `RESEND_API_KEY`, `DIGEST_TO_EMAIL`, `DIGEST_FROM_EMAIL`, `DIGEST_TIME`, `DIGEST_DAYS`, `DASHBOARD_TIMEZONE`). The JSON readers strip a UTF-8 BOM (Notepad/PowerShell add one; without that the file was silently ignored). Changes apply without a restart. `CRON_SECRET` stays env-only. Features hide themselves when their settings are missing.

`POST /api/config` rules: rejects requests whose Origin doesn't match the Host; checks the token against `/api/v1/users/self` and calendar links for `BEGIN:VCALENDAR` before saving; a blank secret field means keep the saved value; changing the Canvas address requires re-entering the token (so a saved token is never sent to a new host). The browser only ever gets `publicConfig()` (token's last 4 characters, calendar count, whether a Resend key exists).

Morning email: `emailProvider` is `gmail` (recommended), `resend`, or empty (off). Gmail sends through `smtp.gmail.com:465` with nodemailer (bundled into the server chunk, not in standalone node_modules) using the user's Gmail address and a 16-letter app password (needs 2-Step Verification; school accounts often block app passwords). `/api/config` validates the fields in `applyEmailSettings` (only fields the form sent change) and runs `transporter.verify()` when the Gmail address/password/provider changes. Resend: without a verified domain it only delivers to the signup email. Configs saved before Gmail existed are treated as `resend` when a Resend key exists.

Daily send: saving email settings calls `lib/schedule.js` → `launcher/schedule-digest.ps1`, which registers the per-user Windows task "School Dashboard Morning Email" (no admin; StartWhenAvailable so a missed run sends at next boot, WakeToRun). The task runs `start-dashboard.ps1 -SendDigest`: quiet mode, starts the server only if port 3000 is free, POSTs `/api/digest` with an Origin header, logs to `email.log` (AppData when installed, `launcher/` in the project), and kills only the server it started. The PC must be on; nothing sends while it's off. Settings reads the task's real next run time (`nextDigestRun`) and shows "Not scheduled yet" instead of claiming it's on. Uninstall (installer and `uninstall.ps1`) removes the task. `/api/digest` POST is same-origin only; GET works only with `CRON_SECRET`. When testing this path, never let it reach a real provider: the user's `.env.local` has a working Resend key.

## Architecture

The token only ever lives on the server. Pattern: browser → our API routes / server components → Canvas.

- `lib/canvas.js`: every Canvas call. `canvasFetch` adds the Bearer token; `canvasGetAll` follows the `Link: rel="next"` pagination. Reads: courses with `include[]=total_scores`, Planner items (`/api/v1/planner/items`, 21 days back to 90 ahead; announcements and calendar events excluded), announcements (45 days), course tabs (to find the A+ Attendance external tool link), recent grades (`/students/submissions?student_ids[]=self&graded_since=...`, 10 days), Canvas calendar events for class sessions, assignment groups for what-if. Writes: planner overrides (marked_complete), planner notes (create/delete), mark announcement read.
- `lib/loadDashboard.js`: the single loader used by both `app/page.js` and the email route. Applies settings, removes hidden classes, drops dismissed announcements, links announcements to matching cards, filters seen grades, builds class sessions (Canvas calendar plus Google events whose title contains the course code or name).
- `lib/settings.js`: `dashboard-settings.json` (gitignored): hidden class ids, display names, colors, manual attendance links, manual class times (`{days:[0-6], start:"HH:MM", end:"HH:MM"}`). Saves go through `updateSettings(patch)`, which merges only the parts sent (validation in `lib/settingsData.js`, tested in `tests/settingsMerge.test.mjs`), so the onboarding class-times step can't wipe names/colors. `GET /api/settings` lists classes for onboarding. Class times use the shared `ClassTimes.jsx` control (onboarding step "When are your classes?" right after Connect, and Manage classes for every class).
- `lib/dismissed.js`: `dashboard-dismissed.json` (gitignored): `announcements` (ids marked Done) and `grades` (seen grade keys `assignmentId:gradedAt`). Writes are serialized through a promise queue.
- `lib/linking.js`: attaches an announcement to a board card when the card title appears as whole words in the announcement title, same course, title at least 5 chars.
- `lib/gradeMath.js`: mirrors Canvas "current grade" (only graded or what-if work counts; weighted courses only count groups with graded work). `scoreNeeded` (one assignment) and `averageNeeded` (uniform % on everything left) solve linearly between 0 and full points. Drop-lowest rules are NOT applied.
- `lib/calendar.js`: any secret iCal link (Google, Outlook, ...) via `node-ical` `expandRecurringEvent` (handles recurrence, EXDATE, moved instances, DST). All-day events are passed as "YYYY-MM-DD" strings. Events with a `event-assignment-` UID (Canvas's own feed) are skipped since the strip already shows Canvas items.
- Calendars: `calendarUrls` (secret, comma-separated) plus `calendarShow` (same order, `classes` | `all`, default `classes`: the user wants personal events off the strip unless turned on). `calendarList()` in config.js pairs them; `publicConfig().calendars` gives Settings only `{kind, show}` (`lib/calendarKind.js` labels Google/Outlook), never links. `/api/config`: `calendars` = saved ones to keep by index with their show, `calendarUrls` = links to add (appended, checked), `clear: ["calendarUrls"]` = remove all. `loadDashboard` shows an event if its calendar is `all` or its title mentions a class (`courseForTitle`, same rule as class sessions); hidden events' dates (not titles) go to the strip for its "N personal events hidden" line. Class-time detection uses all events regardless.
- Settings sections are named by direction so they aren't confused: "Show my calendar here" (linked calendars → strip) and "Send Canvas to my calendar" (Canvas feed → Google/Outlook).
- Canvas feed (Settings, optional, off unless the user clicks): `/api/canvas-feed` reads `users/self/profile` `calendar.ics`, and Settings offers Add to Google (`calendar.google.com/calendar/r?cid=webcal…`), Outlook.com and school Outlook (`…/calendar/0/addfromweb?url=`), or Copy. The subscription lives in the user's calendar app; the dashboard can't turn it off. Not a default: it duplicates Canvas notifications.
- `lib/digest.js` sends; `lib/digestHtml.js` builds the email (pure, no imports; tested in `tests/digest.test.mjs`): three styles: "note" (the user's pick, MAIL-4, used by `lib/digest.js`: "Good morning, <first name>." from the Canvas account, a 1-3 sentence summary from FIXED templates chosen by counts (never AI text), an "On your plate" list overdue→today→week with no duplicates, the newest announcement as a big pull quote, dark Open Canvas button), plus "brochure" and "banner". Both are Outlook-safe: no page/card background, outlined rows, max 720px, color only in the banner/dots/button, one Open Canvas button. Grades and calendar were intentionally removed at the user's request. Email-client rules: tables + inline styles, 600px, system font fallback ('Segoe UI' first, max weight 700), and a full dark palette via `prefers-color-scheme` AND Outlook web's `[data-ogsc]/[data-ogsb]` hooks, keyed on `em-*` classes on every colored element (the user's school inbox is Outlook web in dark mode; without these it turned muddy gray). Preview by rendering HTML only; never send test emails without the user's OK.
- `lib/palette.js`: the 8 course colors.
- `app/components/Dashboard.jsx`: main client component (board, grade tiles, announcements, Smart Check in, theme toggle, toasts). `WeekStrip.jsx`, `QuickAdd.jsx`, `WhatIfPanel.jsx`, `ManageClasses.jsx`.
- API routes in `app/api/`: `planner`, `notes`, `announcements/read`, `announcements/dismiss`, `grades/seen`, `settings`, `whatif`, `digest` (GET for cron with optional CRON_SECRET, POST for the button).

## Behavior decisions (keep these)

- Board order: To do and In progress soonest-due first; Done most-recently-due first (just-submitted work on top). Done hides cards 5 days after their due date (`DONE_KEEP_DAYS`; no-date items stay), using `now ?? loadedAt` (server load time passed from page.js) so the first client render matches the server. The toast sits bottom-center with a close button (the corners hold Done buttons). Every board column shows 8 cards, then "Show X more" / "Show fewer" (`CardList`); announcements collapse after 12. Keep columns consistent with each other.
- Week radar: To do and In progress split into "This week" (due within 7 days of now, or overdue; same window as the "due this week" counter, blue label) and "Later" (plus no-date items). `CardList` `splitAt` never hides This week behind "Show more"; only Later collapses. Done has no split.
- Freshness: the dashboard calls `router.refresh()` every 15 min while visible and when the window regains focus after 3+ min away.
- Links inside draggable cards have `-webkit-user-drag: none` (globals.css) so grabbing a card by its title drags the card, not the URL.
- Tests: `npm test` runs `tests/*.test.mjs` (node:test, no dependencies) with hand-computed expected values for `lib/gradeMath.js`. The release workflow runs them before building, so a failing test blocks the installer. Add a test when changing grade math.
- Board columns: To do / In progress / Done. Only moves into or out of Done touch Canvas (planner override). "In progress" is local only (localStorage key `dashboard-in-progress`). Initial status: override wins, then `submissions.submitted` means Done.
- Class names, not course codes, are shown everywhere; codes appear only as small secondary labels. Default names drop Canvas's term/section suffix (`lib/courseNames.js`: "… (Fall 2026-1 CEN4065-0)" → "…", "Capstone 1 FA 26" → "Capstone 1") and codes become real ones ("80250.202680" → "COP4531", which also helps match calendar events). `applySettings` returns `name` (custom, else default), `defaultName`, `customName`, `canvasName`; Manage classes must edit `customName`, never infer renames by comparing to `canvasName`.
- Layout A "Command sidebar" (DASH-6, the user's pick) is one screen on desktop (xl): a one-row top bar; a left sidebar (288px, 320px from 90rem) with the Next class card over a Grades list (one row per class: mini ring, name → course home, code · % · letter, Check in / What-if / Grades, "N new" opening inline; clicking a row filters, and the list scrolls); the main area has a slim 60px 7-day strip (each day shows its first item and "+N"; hovering or tabbing into a day drops down the full list with links) over [board | announcements (260px, 300px from 90rem)]. The quick-add bar sits in the Assignments heading row with the "Only X ✕" filter chip. Board cards are compact (class + due pill, one-line title with the full title on hover, then date/badges/actions) so a column shows ~5 cards at 1536x790 and ~7 at 1920x970. Each panel scrolls on its own; below xl everything stacks (sidebar, week, board, announcements) and the page scrolls. The user disliked long vertical pages and top rows that squeezed the board.
- Announcements: Done hides and marks read; Clear all respects the class filter; Undo toast for 7 seconds.
- Next class card (`app/components/NextClassCard.jsx`, data from `lib/nextClass.js`, tested in `tests/nextClass.test.mjs`): top of the left sidebar (Layout A); it replaced the old Smart Check in pill. States: later today, starting soon (15 min before: class-colored ring, heads-up only), in class now, next class on a later day, and "Add class times" when none are known. **Check in shows only while class is on (start to end), never before** (user's rule). Shows the class's most urgent not-done item (overdue first) and newest unread announcement from the last 3 days. Class times: Canvas at Florida Poly has none (no course calendar events, section names without times, empty syllabi; checked Sep 2026), so they come from Manage classes / onboarding (`schedule`, wins) or linked-calendar events whose title mentions the class.
- Account chip (`AccountChip.jsx`, top bar right): Canvas `users/self/profile` via `getAccount()` in lib/canvas.js (cached 30 min per token, never blocks the dashboard); Settings shows "Connected as" in the Canvas box.
- Next class card is tinted in the class color (brand tint when empty) so it reads as different from the white panels (user's ask); rows on it use `.row-hover-soft`.
- "Sending you to …" card + pop-up window (`RedirectCard.jsx`, mounted in layout; DASH-9): a plain click on an outside link that no other handler took (`defaultPrevented`) shows the card, then after `OPEN_MS` (1.4 s, matches `.redirect-bar`; the card stays 0.3 s more, then fades) opens it in ONE named pop-up window (`dashboard-peek`, ~85% of the dashboard window, min 900x650, centered on it and kept on screen) instead of a full browser window: `window.open("", name, "popup,…")`, then `opener = null` while it is still blank (so outside pages can't steer the dashboard), then `location.href`, then `focus()`; repeated clicks reuse it. If pop-ups are blocked (null), it falls back to a normal `noopener` open. It shares the browser's Canvas sign in, so Check in works. Ctrl/Shift/Alt/middle clicks open normally with no card.
- Quick look (`QuickLook.jsx`, DASH-9): a plain click on a board card title, a week-strip item, the Next class card's urgent item or announcement, a card's linked announcement, or an Announcements row opens an in-app pop-up (same `.modal-*` pattern as What-if) instead of Canvas, because Canvas forbids framing (`frame-ancestors`). Supported: Planner `assignment`, `quiz` (classic quiz + its assignment for the submission), `discussion_topic`, and announcements; other kinds (pages, peer reviews) go to the pop-up window, notes have no link. `GET /api/quicklook?type&courseId&id` → `getQuickLook()` in lib/canvas.js (ids via `canvasId`, 404 → friendly text) returns only what the pop-up shows; teacher HTML is cleaned on the server by `lib/sanitizeHtml.js` (sanitize-html allowlist: formatting, lists, tables, headings (h1/h2 → h3), links, images; every href/src through `safeUrl` against the Canvas base; links get target=_blank rel=noreferrer; tested in `tests/sanitizeHtml.test.mjs`) and is the ONLY thing rendered with `dangerouslySetInnerHTML` (`.quicklook-content` typography in globals.css). Footer: the card's Start / Back to To do / Done / Reopen (Dashboard's `moveItem`) or the announcement's Done (`dismissAnnouncements`), plus Open in Canvas (→ pop-up window). Opening an announcement marks it read (as clicking it always did). Skeleton while loading, friendly error with Open in Canvas. Ctrl/middle clicks still go straight to Canvas. Canvas images inside instructions load only when the browser is signed in to Canvas.
- Settings opens as a centered pop-up over the dashboard (SET-3): an intercepting route in a parallel slot, `app/@modal/(.)setup/*` + `app/@modal/default.js`, rendered by `app/layout.js` as `{modal}`; `SettingsModal.jsx` is the frame (Escape/backdrop/Close = router.back()). Links to Settings must be `next/link` (`<Link href="/setup" scroll={false}>`) so they open the pop-up; a direct load of `/setup` still shows the full page (Onboarding when not configured, `?fix=token`). Both routes load data through `app/setup/settingsProps.js`, which returns local settings at once and passes `account` and `nextEmail` as unawaited promises (read with `useSettled`/`use()` inside small Suspense boundaries); `nextDigestRun()` (a ~1 s PowerShell call) is cached 60 s. The pop-up has a fixed height (`.settings-dialog`) and a skeleton shaped like the form, so nothing jumps. No full-screen loading screen for Settings.
- Onboarding walkthrough (CLASS-2): `/setup?tour=1` shows every onboarding step with nothing saved (`lib/tour.js` answers the saves locally; `app/setup/tourProps.js`). Settings has a "Walk through setup" button; it must be a plain `<a>` (full load), since a client-side move to /setup is caught by the Settings pop-up route.
- Course codes (DASH-5) show under class names via `displayCode(course)` in lib/courseNames.js ("CEN 4065"; real codes only, fallbacks like "Capstone1_FA2026" show nothing).
- What-if and Manage classes are centered pop-ups (`.modal-backdrop/.modal-in/.modal-glow` in globals.css): Escape/backdrop/Close close them, focus is trapped and returned.
- Phone access is on hold (user's call): the server is 127.0.0.1-only, so phones can't reach it. Phone designs are on the canvas for later.
- Grades panel (sidebar, `GradeRow` in Dashboard.jsx): clicking a row filters the page; the class name link opens the Canvas course home; new grades show as an "N new" chip that opens the new-grades list inside the row with Got it.
- Theme: CSS variables in `app/globals.css` (light default, dark via `prefers-color-scheme` or `data-theme`). A script in `app/layout.js` applies the saved `dashboard-theme` before paint. Use the variables (`var(--ink)`, `var(--surface)`, `var(--red-bg)`, etc.), never new hard-coded grays. Every token must be defined in all three blocks (light `:root`, the dark media query, `[data-theme="dark"]`).
- Look ("Confetti Grid", chosen by the user; design canvas: https://claude.ai/artifact/7K1SwWYtiNXiB9trngdMm4, which is the source of truth for the redesign): warm off-white `--bg`, white cards, one blue `--brand` for actions (+ `--brand-hover/-press/-tint/-text/-ring`), class colors for everything class-related. Fonts: Figtree body (`--font-sans`), Bricolage Grotesque for headlines and numbers (`font-display` class). Buttons use `.btn` + `.btn-primary | .btn-secondary | .btn-soft | .btn-danger` from globals.css (hover, press edge, disabled built in); don't hand-style buttons. The redesign ships in stages: foundation (tokens, fonts, buttons) and the lighter dashboard layout (week strip panel, grade rings, borderless columns, announcements list) are done; next centered pop-ups (What-if, Manage classes, "Sending you to Canvas"), then the Banner morning email. The email has only an "Open Canvas" button: the user declined an "open the app" link that would need GitHub Pages.
- Consistency (the user wants no element looking more polished than another): scrollbars, focus ring (`--focus`), select chevron (`--chevron`), checkbox accent, date/time picker icons and placeholders are styled globally in `globals.css`, so don't restyle them per component. Modal backdrops use `bg-[var(--overlay)]`. Every clickable thing needs a visible hover, not just a cursor change: fields and dropdowns get a hover outline and a 2px `--focus` ring while focused (global in globals.css); Settings boxes use `.settings-card` (outline on hover, brand highlight via `:focus-within`); collapsible headings use `.fold-summary` + `.fold-title` + `.fold-chevron`; plain text links use `.text-link`. Text fields: `rounded-lg bg-[var(--field)]`, no border. Radii: pills `rounded-full` for top-bar and chip buttons, `rounded-md` for small badges and card buttons, `rounded-lg` for fields and form buttons, `rounded-xl`/`rounded-2xl` for panels. Check light and dark after UI changes.
- Setup help: each field on `/setup` has a "How do I find this?" dropdown (`Help` in SetupForm) with numbered steps and direct links (Canvas `/profile/settings` built from the typed address, Google Calendar settings, Resend signup and API keys). Keep these accurate if those sites change.
- Course colors: set `--c` inline on the element (dynamic Tailwind class names would not compile), then use `.c-dot`, `.c-tint`, `.c-text`, `.btn-course` from globals.css, which mix the tint and readable text for light and dark. Cards use `.task-card` (hover ring in the class color), panels `.panel`, list rows `.row-hover`. No colored left borders.
- Relative times and dates render only after mount (`now` state) to avoid hydration mismatches and to use the browser's timezone.

Read and write cards with the `ArtifactData` tool on that URL; never republish the page itself unless asked (if you must, read it first with the `Artifact` tool and keep its `db` capability).

- Cards live in collection `tasks`, doc id = task id lowercased (`dash-6`). Fields: `id, title, note, status, next, github, installer, createdBy ("you"|"claude"), createdAt, updatedAt, seen, thread`, plus mirrors of the latest messages: his `decision ("good"|"revise"), yourNote, yourAt`, Claude's `claudeNote, claudeAt`, and `sealedAt/reopenedAt`.
- `status` columns: `backlog`, `progress` (Claude working), `you` (needs his pick/test/answer), `revise` (he asked for changes), `ready` (done and pushed; he can seal), `sealed`, and `parked` (a folded "Parked ideas" drawer, not a column). His "Needs revision" moves a card to `revise`, "Good to go" to `ready`.
- **Only he seals.** Never set `sealed`. Sealed cards can be reopened (→ `revise`).
- **`thread`** is the full conversation per card: `[{by: "you"|"claude", decision, text, at}]`, oldest first. Always read the card, append one entry, and write the whole array back pinned with `if_version`; never replace or drop entries (he once lost a comment that way). If the write is refused because the card changed, re-read and redo it.
- Timestamps: take the real time from the shell (`date -u +%Y-%m-%dT%H:%M:%SZ`) right before writing; never guess.
- When he says "check the tracker" (and at the start of a work round): `query` `tasks` where `seen == false`, plus `get` `feedback/general` (his general notes: `yourNote/yourAt`; answer with `claudeNote/claudeAt`). Act on them, then update each card with the reply, `seen: true`, and the new `status`/`next`.
- Move cards as work progresses (`progress` → `you` or `ready`) and set `github: true` when pushed, `installer: true` when in a published release.
- New cards get the next number in their area. Areas: DASH Dashboard, CLASS Classes, CAL Calendars, MAIL Email, SET Settings, SAFE Safety, REL Releases, PARK Parked. IDs never change.
- Write card text plainly for him (no file paths needed). Label any preview built on made-up data as "example data".
